How it works

1 · Describe

Say what you want in English.

You describe the tool in plain English. Claude writes a complete MCP server for it, with real API calls, typed inputs, and clear errors. No spec to supply, no boilerplate to write.

2 · Chat

Talk to your new agent.

Your browser loads the new server's tools and hands them to Claude. Ask for something, and Claude picks the right tool, calls the API, and answers.

3 · Verify

Prove it doesn't lie.

Tempered feeds every tool bad input on purpose and watches how it reacts. The risky case is silent success: a tool accepts junk and reports OK anyway. Tempered catches that before your agent trusts it.

What's next

  1. Near-term
    More preset connectors, and GitHub Actions support. A ready-made set of common APIs that work out of the box, plus tempered test as a CI check so a broken API spec fails the build.
  2. Mid-term
    Monitoring that keeps running after launch. Keep checking MCP servers once they ship, and flag any that quietly start accepting bad input again.
  3. Mid-term
    A public "verified" badge for MCP servers. A pass rate any vendor can show next to their listing, and that anyone can re-run to check for themselves.
  4. Long-term
    The check every server runs before it ships. Registries and agent platforms run Tempered before they list a server, so the broken ones never reach agents at all.
